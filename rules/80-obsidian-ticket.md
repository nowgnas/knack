# Obsidian 티켓 문서

- 현재 브랜치명에 `[A-Z][A-Z0-9]+-\d+` 형태의 티켓 키가 있으면(예: `feature/CONSUMER-286`, `bugfix/FRDEV-6781`) 티켓 관련 작업으로 본다. 브랜치에 없으면 사용자가 대화에서 같은 형태의 티켓 번호를 직접 언급했을 때만 적용한다. 둘 다 아니면 이 룰은 적용하지 않는다.
- 적용 대상이면 작업을 진행하기 전에 Obsidian의 해당 티켓 노트를 먼저 찾아 읽는다.
- vault 경로는 `~/.config/knack/obsidian-vault.local.yml`의 `vault_path`와 `work.folder`(기본값 `Work`)를 쓴다. 설정이 없으면 임의 경로를 추정하지 말고 사용자에게 `obsidian-daily` 룰의 설정 방법을 안내한다.
- 티켓 문서의 새 위치는 `{vault_path}/{work.folder}/{티켓키}-{과제명}/`이다. 과제명은 Jira 제목 또는 사용자 제공 제목을 사용하고 파일명에 쓸 수 없는 문자를 정리한다. 제목을 확인할 수 없으면 추정해서 폴더명을 만들지 않는다.
- 먼저 `rg --files` 등으로 `{work.folder}` 아래를 재귀 검색한다. 기존 연도별·개인별 경로도 읽는다. 같은 티켓의 여러 문서는 정상이다. `jira` frontmatter와 파일명을 확인해 대표 티켓 노트(`{티켓키}-{과제명}.md`)와 관련 문서를 구분하고, 서로 다른 과제가 실제로 중복될 때만 사용자에게 확인한다.
- 대표 노트의 frontmatter(`jira`, `status`, `service`, `deploy`, `related`), 배경·현재 상태·남은 일과 작업에 필요한 역할별 문서를 읽어 맥락을 파악한다. 같은 세션에서는 이미 읽은 내용을 반복 조회하지 않는다.
- 티켓을 검토하며 Obsidian 문서를 작성할 때는 위 폴더에 대표 노트를 목차·요약으로 두고, 내용의 목적에 따라 별도 Markdown 파일을 만든다. `파악.md`에는 현상·재현·코드/DB 흐름·근거, `검토.md`에는 대안·영향도·리뷰, `구현.md`에는 실제 변경·검증·배포 상태, 구체적인 설계는 `변경-방향.md`처럼 주제명 파일에 둔다. 필요한 범주만 만들고 빈 파일은 만들지 않는다.
- 한 사실의 상세 내용은 한 파일에 두고 대표 노트에는 결론과 Obsidian 내부 링크를 남긴다. 범주가 바뀌면 해당 문서에서 갱신하고, 출처·확인 범위·미확인 사항을 유지한다. 기존 문서를 옮기거나 나눌 때 본문과 외부 링크·백링크를 보존하고 새 경로 및 내부 링크를 검증한다.
- 노트 내용을 레포로 복사하거나 커밋하지 않는다. 같은 세션에서는 이미 읽은 노트를 다시 찾지 않는다.
