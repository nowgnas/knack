# 고위험 변경의 완료 게이트

"테스트 몇 개 통과"만으로 완료를 판단하기 어려운 변경에 쓴다. 설계 단계에서 `GATES.md`를 써서 승인받고, 완료 보고 직전에 전부 다시 실행한다.
unlazy(https://github.com/Leonxlnx/unlazy, MIT)의 게이트 형식과 규칙 중 단일 기능·버그 작업에 필요한 부분만 가져왔다.

## 1. 적용 대상
하나라도 해당하면 고위험이다. 애매하면 사용자에게 묻는다.
- DB 스키마 변경, 백필, 데이터 보정
- 금액 계산, 결제·정산·환불, 포인트·쿠폰 차감
- 동시성: 락, 버전, 멱등키, 중복 요청 처리
- 메시지·이벤트: 발행 시점, 재처리, 순서, 스키마 호환
- 여러 모듈에 걸친 리팩터링 (동작 보존이 목표인 변경)

경량 규모이거나 위에 해당하지 않으면 쓰지 않는다. 게이트를 쓰고 돌리는 것도 비용이다.

## 2. GATES.md 작성
위치는 `.design/<slug>/GATES.md`, 템플릿은 `knack show template GATES`.
- 게이트 하나 = 관찰 가능한 결과 하나. 제목은 활동("테스트 작성")이 아니라 결과("같은 멱등키 동시 요청은 한 건만 승인된다")로 쓴다.
- 자동 게이트: 들여쓴 `CHECK:`(명령)와 `EXPECT:`(성공할 때만 나오는 출력, `/정규식/플래그` 가능)를 둘 다 쓴다. 통과 = exit 0 **그리고** EXPECT 일치. 실패 종료는 출력이 맞아도 실패다.
- 수동 게이트: 명령으로 판정할 수 없을 때만 쓴다(예: 배포 순서 팀 합의). CHECK·EXPECT 없이 쓰고, 확인한 뒤 `[x]`로 체크하고 `EVIDENCE:`에 확인한 사실 한 줄을 적는다.
- `CWD:`(선택)는 레포 루트 기준 상대 경로. `EVIDENCE:`는 `knack gate`가 채운다.
- EXPECT는 전체가 통과했을 때만 나오는 문자열로 고른다. 예: `BUILD SUCCESSFUL`, `/Tests run: \d+, Failures: 0, Errors: 0/`.
- 음성 대조: "없어야 한다"를 검사하는 게이트는, 있는 경우에 실제로 실패하는지 먼저 확인한다(빈 결과로 통과하는 가짜 게이트 방지).
- 숫자는 독립적으로 잰다. 요청서의 숫자를 EXPECT에 그대로 옮겨 자기 증명으로 쓰지 않는다.
- `echo ok`처럼 코드와 무관하게 같은 출력을 내는 CHECK는 게이트가 아니다. `knack gate`가 경고한다.

## 3. 백엔드 게이트 예
| 영역 | 결과 | CHECK 예 |
|---|---|---|
| 마이그레이션 | 구 코드 + 새 스키마에서 기존 테스트가 통과한다 | 이전 커밋의 테스트를 새 스키마(Testcontainers)로 실행 |
| 마이그레이션 | down 적용 후 스키마가 적용 전과 같다 | 로컬 DB에 up → down → 스키마 덤프 diff |
| 금액 | 반올림·통화 경계값 표가 전부 일치한다 | 경계값 파라미터 테스트 |
| 동시성 | 같은 멱등키 동시 N건 → 승인 1건 | 동시 요청 통합 테스트 |
| 메시지 | 같은 메시지를 두 번 소비해도 상태는 한 번만 바뀐다 | 중복 소비 통합 테스트 |
| 리팩터링 | 변경 전후 공개 API 응답이 같다 | 골든 파일 비교 테스트 |

운영·공유 환경에 닿는 CHECK는 쓰지 않는다(`30-backend-safety`). 로컬 DB, Testcontainers, 임시 파일만 쓴다.

## 4. 승인 — 설계 게이트에서 함께
- PLAN.md(버그면 BUGFIX.md의 수정 계획)와 함께 GATES.md를 보여주고, `knack gate status <경로>` 출력으로 파싱 결과와 실행될 명령을 제시한다.
- 사용자가 게이트 명령 목록을 승인하기 전에는 `knack gate run`을 하지 않는다. 승인 뒤 게이트를 바꾸면 다시 보여준다.

## 5. 실행과 재검증
| 명령 | 동작 |
|---|---|
| `knack gate status <GATES.md>` | 실행하지 않고 상태와 경고만 본다 |
| `knack gate run <GATES.md>` | 아직 충족되지 않은 자동 게이트만 실행하고 EVIDENCE를 기록한다 |
| `knack gate reverify <GATES.md>` | 충족된 것까지 **전부** 다시 실행한다. 예전 증거는 지금 코드의 증거가 아니다 |

- 명령은 GATES.md가 속한 git 레포의 루트에서 실행된다.
- 게이트 정의(CHECK·EXPECT·CWD)를 바꾸면 이전 증거는 무효가 된다.
- 종료 코드: 0 ALL MET · 1 미충족 또는 포기 있음 · 2 형식 오류.

## 6. 불가능한 게이트 — ABANDON
- 게이트를 지우거나 조건을 몰래 낮추지 않는다. 파일 맨 앞 열에 `ABANDON: <id> <이유와 인계 대상>`을 적는다.
- 포기가 하나라도 있으면 `knack gate`는 HANDOFF REQUIRED로 끝난다. 완료가 아니라 **인계**로 보고한다.

## 7. 완료 보고 전 감사
1. 원래 요청과 성공 기준을 다시 읽고, 게이트가 빠짐없이 덮는지 확인한다.
2. `knack gate reverify`를 실행한다. ALL MET이 아니면 완료라고 보고하지 않는다.
3. 보고에 쓰는 숫자(건수, 소요 시간, 커버리지)는 방금 다시 잰 값만 쓴다.
4. PLAN.md 9절·BUGFIX.md의 완료 게이트 표에 게이트별 결과와 포기 항목을 적는다.
