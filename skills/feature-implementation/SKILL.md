# Feature Implementation

정책이 확정되고 설계가 승인되기 전에는 소스 코드를 수정하지 않는다. 승인 뒤에는 완료 기준까지 멈추지 않고 진행한다.
단계별 세부 절차는 필요한 단계만 읽는다: `knack show ref feature-workflow --section <번호>`.
참조 문서(목차부터): `policy-checklist`, `conventions`, `readable-code`, `db-migration`, `high-risk-gates` → `knack show ref <이름> --toc`.

## 규모
| 규모 | 기준 | 진행 |
|---|---|---|
| 경량 | 모듈 2개 이하, 정책·데이터 모델·API 계약 변경 없음 | 계획을 대화로 제시 → 승인 → 구현 → 대화 보고. **파일 없음** |
| 표준 | 모듈·파일 3개 이상이거나 정책·데이터 모델·API 계약이 바뀜 | 모든 단계. `.design/<slug>/PLAN.md` **한 개** |

애매하면 표준으로 한다. "설계 없이 바로 해줘"라고 하면 경량으로 하되 가정을 보고에 남긴다.
**고위험**(스키마·데이터 보정, 금액·결제·정산, 동시성·멱등성, 메시지 재처리, 대규모 리팩터링)은 표준으로 하고 완료 게이트 `GATES.md`를 더한다 → `knack show ref high-risk-gates`.
계획 파일은 구현하면서 같이 고친다. 사후 요약 파일은 만들지 않는다 — 결과는 같은 `PLAN.md`의 9절에 덧붙인다.

## 흐름
1. 요구사항: 목표·비목표, 테스트로 옮길 수 있는 성공 기준
2. 정책 점검: 항목별 ✅ 명확(근거) / ❓ 불명확(질문) / ⚠️ 가정(기본값 제안)
3. 코드 맥락: 가장 비슷한 기존 기능을 레퍼런스로 컨벤션 추출. `.onboarding/`이 있으면 필요한 섹션만
4. 설계: 표준이면 `templates/PLAN.md` → `.design/<slug>/PLAN.md`. 스키마가 바뀌면 `db-migration` 적용. 고위험이면 `templates/GATES.md`도
5. 게이트 (아래)
6. 구현: 레퍼런스와 같은 구조, `readable-code` 기준, 설계 밖 리팩토링 없음. 성공 기준 테스트는 먼저 실패를 확인하고 구현한다
7. 검증: 빌드, 신규·영향 테스트, 린트·포맷터. 고위험이면 `knack gate run`
8. 리뷰: 4단계 셀프 리뷰 후 `impl-review`로 독립 리뷰 (경량은 생략 가능). 결과는 대화와 `PLAN.md` 9절에 적는다
9. 결과: `PLAN.md` 9절(검증·게이트·리뷰·후속)을 채우고 대화로 보고. 경량이면 대화 보고만

## 5. 게이트 — 구현 시작 조건 (Definition of Ready)
❓ 질문(선택지와 추천안 포함), ⚠️ 가정, 설계 요약을 한 번에 제시한다. 다음이 모두 충족되면 구현을 시작한다.
- [ ] 모든 ❓에 답이 있거나 해당 가정이 승인됨
- [ ] 설계가 명시적으로 승인됨 ("진행해" 등)
- [ ] 성공 기준과 테스트 계획에 합의함
- [ ] 고위험이면 `GATES.md`의 게이트와 실행될 명령(`knack gate status` 출력)이 승인됨

충족 전에는 소스·설정·마이그레이션을 수정하지 않는다. 조회, 빌드, 기존 테스트 실행은 해도 된다.
에이전트에 읽기 전용 계획 모드(Claude Code plan mode 등)가 있으면 그 승인으로 이 게이트를 대신한다 — 경량은 그것만으로 끝낸다.

## 승인 후 진행 방식
- **묻지 않고 한다**: 로컬 빌드·테스트·린트·포맷터 실행, 요청한 변경 때문에 생긴 실패 수정, 영향받는 테스트 재실행, 로컬 DB·Testcontainers·임시 파일 사용.
- **멈추고 묻는다**: 새 정책 결정이 필요할 때, 설계 범위를 넘을 때(새 라이브러리·패턴·계층 포함), 운영·공유 환경에 닿을 때, 같은 실패를 세 번 고쳐도 해결되지 않을 때.
- 첫 구현 뒤 중간 보고를 하지 않는다. 완료 기준까지 진행한 뒤 한 번 보고한다.

## 완료 기준
성공 기준을 검증하는 테스트 통과 + 빌드·린트 통과 + 독립 리뷰의 🔴·🟠 반영 + 표준이면 `PLAN.md` 9절 작성.
고위험이면 보고 직전 `knack gate reverify`가 ALL MET이어야 한다. 포기(`ABANDON`)가 있으면 완료가 아니라 인계로 보고한다.
실행하지 못한 검증은 이유와 함께 보고한다.
