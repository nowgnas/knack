# STE Explain

ASD-STE100의 목표는 오독의 두 원인을 없애는 것이다: 뜻이 여러 개인 단어, 두 가지로 읽히는 문장.
설명을 이 규율로 쓰면 장황함·얼버무림·비유가 빠지고 사실과 절차만 남는다.
규칙별 세부와 전후 예시: `knack show ref ste-rules --section <번호>`.

## 1. 모드 고르기
| 모드 | 언어 | 기준 | 고르는 조건 |
|---|---|---|---|
| `strict` | 영어 | STE 규칙을 모두 지킨다. 승인 어휘 안에서 쓰고, 기술 용어만 예외 | "strict", "STE 그대로", "영어로" |
| `80` | 영어 | 핵심 규칙(문장 길이, 능동태, 한 단어 한 뜻)만 지키고 어휘 제한은 푼다 | "80%", "적당히", "가볍게" |
| `ko` | 한국어 | STE 원칙을 한국어 문장에 옮긴다. STE 준수가 아니라 STE식 문체다 | 모드 언급이 없고 한국어 대화일 때 (기본) |

- 모드를 밝히지 않았으면 대화 언어로 정한다: 한국어 → `ko`, 영어 → `80`.
- 답변 첫 줄에 모드를 적는다: `[STE: ko]`.

## 2. 원본 읽기
- 코드·에러·문서가 대상이면 먼저 읽는다. 추측으로 설명하지 않는다.
- 확인하지 못한 내용은 `(추정)`으로 표시한다. STE 문체여도 근거 규칙(`path:line`)은 그대로 따른다.

## 3. 쓰기 — 모든 모드 공통 핵심
1. 한 단어는 한 뜻으로만 쓴다. 용어를 한번 정하면 동의어로 바꾸지 않는다.
2. 한 문장에는 사실 하나, 지시 하나.
3. 지시문 20단어 이하, 서술문 25단어 이하. `ko`는 지시문 12어절, 서술문 15어절 이하(어림값).
4. 능동태로 쓴다. 누가 무엇을 하는지 주어를 드러낸다.
5. 지시어("이것", "그", "it", "this") 대신 대상 이름을 다시 쓴다.
6. 명사 3개 이상을 이어 붙이지 않는다. 풀어서 쓴다.
7. 지시는 명령형으로 쓰고, 조건은 지시 앞에 둔다: "X이면 Y를 한다."
8. 경고·주의는 해당 절차 앞에 둔다.
9. 비유·수사·얼버무림("아마도", "어느 정도", "basically")을 쓰지 않는다.
10. 한 문단은 한 주제. 문단은 6문장 이하.

## 4. 출력 구조
1. **무엇** — 한 문장 정의
2. **왜** — 이것이 존재하는 이유, 바뀌는 결과
3. **동작 / 절차** — 번호 목록. 한 항목에 한 단계
4. **주의** — 실패 조건과 그때 할 일
- 사용자가 다른 구조를 요청하면 그 구조를 따른다. 문체 규칙은 유지한다.

## 5. 끝내기 전 점검
- 문장 길이, 수동태, 지시어, 동의어 교체를 한번 훑어 고친다.
- `strict`에서 승인 어휘 밖 일반 단어가 남으면 승인 단어로 바꾼다. 확신이 없으면 더 짧고 흔한 단어를 고른다.

## 하지 않는 것
- 규격 문서나 승인 단어 사전을 생성·인용하지 않는다(규격 저작권은 ASD에 있다). 모델이 아는 규칙으로 쓴다.
- 파일을 만들지 않는다. 결과는 채팅 답변이다.
- 청중 맞춤 비유가 필요한 요청은 `eli5`가 맞다.
